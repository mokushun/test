# 都道府県ボードゲーム レビュー（2026-11-14）

対象：`index.html`、`README.md`、`prefecture-cards.js`、`CARD_TASK.md`
方針：今回は読み取りレビューのみ。ゲーム本体・説明書・カードデータは変更していない。

## 確認できた点

- 2人の開始位置は北海道（PREFS index 0）・沖縄（46）、3人目は静岡（21）。人数に応じて固定され、開始時にプレイヤー配列をシャッフルしている。
- 各ラウンドで全プレイヤーが1回ずつ行動し、12ラウンドで終了する。したがって各プレイヤー12回ずつ。
- 移動中は到着処理を呼ばず、移動完了後にだけ `resolveArrival()` を呼ぶ。通過県では獲得・対決しない。
- 未所有県は到着者が獲得。他人の所有県では攻撃ロールと防衛ロールを比較し、防衛側に+1、同点は防衛成功（攻撃側が防衛合計を上回った場合だけ奪取）。
- 所有権は県の色・カード一覧・県詳細表示に数値プレイヤーIDで反映される。地方ボーナスは同じ地方の所有数3以上で+3点。
- READMEの現行ルールは実装と概ね一致。
- カードデータは47件、JIS順、重複なし。8必須フィールド（title / emoji / specialty / fact / question / choices / answer / explanation）は全47件に存在する。

## 修正・判断を推奨する点

### P1：ログの日付表示が壊れる
`dateLabel()` は `S.round` を参照するが、現在の状態は `S.turn` を使い、`S.round` は初期化されていない。ログの先頭が「NaN年目NaN月」になる。現在の12ラウンド制なら `S.turn` を使うか、「第nターン」に変更する。

### P1：同点時の勝者が未定義
結果画面は合計点、次に所有県数で並べる。両方同じ場合は、シャッフル後のプレイヤー配列順で先頭が単独優勝扱いになる。ルールに同点処理がないため、同点優勝にするか、所有県数で決めた後も同点なら引き分けにするなど、仕様を決めて表示を合わせる。

### P2：旧ゲーム（物件購入・賃料・決算）のコードが残っている
`resolveTile()`、`settlement()`、`arriveDestination()`、`ownsRegion()`、`propValue()` など、旧ルールの関数・データが残る。現在の実行経路は `playTurn() → movePlayer() → resolveArrival()` なので、確認した範囲では旧関数は呼ばれていない。ただし旧コードは所有者を `{player, level}` として扱う一方、現行コードは整数IDを使うため、誤って再利用すると不具合になる。別作業で不要な旧コードを整理するのが望ましい。

### P2：カード制作タスクの文書が未完了状態のまま
`CARD_TASK.md` は「カードデータ作成後、別作業で本体に統合」と記載しているが、READMEと実装では統合済み。ファイル冒頭に「完了」と完了日を追記し、次段階も完了に直すと、他AIが同じ作業を再開しない。

## 実機確認で残ること

コードの読み取りだけでは、ブラウザでの操作感・地図スクロール・分岐ピンのタップ・カードの裏返し・対決演出は保証できない。2人/3人それぞれで、12回終了、スタート県カード、未所有県獲得、他人県への挑戦（勝ち・負け・同点）、カード移動、地方ボーナス、最終順位を確認する。
